Patching Kickstart 1.3 to boot from internal IDE

Motivation: Kickstart 1.3 can not boot from the IDE controller of the Amiga 600/1200 or the CFIDE68K controller (an A600/A1200 IDE compatible controller for the 68000 CPU socket) since the scsi.device (which is the driver for the IDE controller) was not yet present in this Kickstart version. There is a tool called GetSCSI11 on Aminet which extracts the scsi.device from a Kickstart 3.x ROM and patches it to make it usable using Mountlist entries in Kickstart 1.3, but still does not allow to boot using it. I wanted to use my compact flash card on my CFIDE68K controller as boot device so I had a look how this could be done.

What does this patch do?: The scsi.device uses the method AddBootNode() in expansion.library which was introduced in Kickstart 2.0 to add the partitions on the disk to the operating system. GetSCSI11 adds a version check and does not call this method in case it is running in Kickstart 1.3 (this is why it is necessary to create mountlist entries for adding the partitions to the operating system). Instead of using AddBootNode() it is necessary in Kickstart 1.3 to manually create a boot node and enqueue it into the boot node list of the expansion.library. This is equivalent code to AddBootNode() for Kickstart 1.3. I've created a patch which, basing on a scsi.device from GetSCSI11 executes this code in case the scsi.library is used from Kickstart 1.3. For being able to boot using the patched scsi.device it is necessary to make it available at boot time (i.e. to put it into the ROM). The solution I've chosen was to create a 256kB ROM that maps into $F80000 (Kick 1.3 is right after that at $FC0000) which contains the scsi.device ($F80000 would normally be a mirror of the Kickstart in $FC0000). This requires a small change to the Kickstart ROM to also scan the range from $F80000 to $FC0000 for ROM residents.

What do I need to build a patched ROM?: To build a 512kB ROM that contains the patched scsi.device and the patched Kick 1.3 you need the following:

  • A scsi.device from Kickstart 3.0 - A1200 (Kick v39.106, scsi.device v37.64), Kickstart 3.1 - A1200 (Kick v40.68, scsi.device v40.12) or a SCSI4345p.lha (Aminet) patched scsi.device. The scsi.device can either be obtained by extracting it from a ROM image using RomSplit or using GetSCSI11.
  • A ROM image of Kickstart 1.3 (v34.5).
  • A 27C400 EPROM (or compatible larger one), and a EPROM programmer to write to it.

How to build a patched ROM: You can either patch your scsi.device to get a version for Kick 1.3 (if you want to build your rom using Remus yourself) or you can use a patch which directly outputs a ROM image.

  • Download the patches.
  • Patch your Kickstart 1.3 image (using the gpatch tool from Aminet): gpatch kick34005.A500 kick34005.A500.gpatch kick34005.A500_patched
  • Extract your 3.x (A1200) scsi.device using RomSplit or GetSCSI11.
  • Apply the scsi.device-to-rom-file patch: gpatch scsi.device scsi.device_xx.xx(A1200)_rom.gpatch scsi_device.rom RECURSIVE
  • Merge the scsi_device.rom and the patched Kickstart: join scsi_device.rom kick34005.A500_patched TO kick1.3_scsi.rom
  • Write the ROM file to an EPROM (don't forget to swap bytes).
Instead of applying the scsi.device-to-rom-file patch you can also just patch your scsi.device and build your ROM yourself (in case you want to add other residents to the ROM too):
  • Apply the scsi.device patch: gpatch scsi.device scsi.device_xx.xx(A1200).gpatch scsi.device_ks13_patched RECURSIVE
  • Build a 256kB ROM (base address $F80000) using Remus which contains a romheader (source), the patched scsi.device and whatever else you want to be in the ROM. The romheader points to the start address of the exec.library ($FC00D2) (this is necessary since now instead of the Kickstart ROM the newly built ROM is mapped to the start of the address space on boot-up.
  • Merge and write the ROMs as described before.

Known Issues/Limitations: For some reason the modified Kickstart does not boot from the scsi.device on power-up in my A500+ with CFIDE68K controller (I get the insert Workbench disk image). After resetting the Amiga it boots from the hard disk. I'm not sure what causes this (some hardware initialisation?), it boots immediately in UAE with A600/A1200 IDE emulation.

I tried to do as few modifications as necessary to keep it as compatible to the unmodified Kick 1.3 as possible, but there might be programs (games) that do not work with the modified version because:

  • The Kickstart mirror at $F80000 is replaced by the ROM containing the scsi.device
  • The scsi.device allocates some memory (and loads the filesystem into RAM).
  • There is a minimal change to the Kickstart itself to scan the new ROM area.
The ROM can not be used in tools like BlizKick since they need to patch the parts of the ROM and do not recognise the patched ROM as a Kick 1.3 ROM anymore (i.e. you have to write it to a EPROM to use it).

Creating the partitions on the harddisk/compact flash: This is not really specific to the patched ROM, but still it might be useful if you want to use a large hard disk/compact flash card with Kickstart 1.3. The Rigid Disk Block (RDB) contains information about the structure of the disk, to obtain these values I've used HDToolBox on a AmigaOS 3.9 system, since you have to know these values if you want to initialize a disk using a Kick 1.3 version of HDToolBox (which has no option to detect them automatically). I've used the A590 Setup disk of the Commodore A590 HD controller to setup the partitions on the disk. The setup disk contains a Kick 1.3 version of HDToolBox. You have to add the FastFileSystem to the filesystems installed on the disk, since Kick 1.3 does not yet have it in the ROM. You can either use FastFileSystem 36.3 of Workbench 1.3 (in the L: directory) or version 40.1 (which was included in Workbench 3.1), which still works on Kick 1.3 (newer versions do not work since they depend on features not present in Kick 1.3). Version 40.1 has the advantage that it requires far less memory for large harddisks (v36.3 requires more than 1MB of RAM for a hard disk of 4GB size, v40.1 only requires a few kB). The disadvantage of v40.1 is that you will get an additional icon (e.g. DH0:DOSA) for every partition on your workbench since it seems that the mechanism to register a filesystem changed a bit between those two versions (I have not found out what exactly changed yet, but it is only a cosmetic problem). When creating the partitions make sure not to use anything above the 4GB border since FastFileSystem (at least those versions which are compatible with Kick 1.3) does not support partitions above 4GB. You also should be aware that disk validation (which e.g. is required if your system crashes while writing to the disk) of large disks requires quite a lot of memory.
