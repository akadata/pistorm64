# 68020/68040 JIT Support Implementation

## Summary

The m68xkcpu JIT has been extended to support 68020/68040 CPUs. Previously, the JIT was gated to 68000-only mode and would fall back to Musashi for any 68020+ CPU configuration.

## Changes Made

### 1. CPU Type Check Removed (`src/emulator.c`)

**Before:**
```c
static int m68xkcpu_jit_cpu_supported(unsigned int type) {
  /* Current translator/opinfo is 68000-only. */
  return (type == M68K_CPU_TYPE_68000) ? 1 : 0;
}
```

**After:**
```c
static int m68xkcpu_jit_cpu_supported(unsigned int type) {
  /* JIT supports 68000-68040. Unsupported instructions fall back to Musashi. */
  switch (type) {
  case M68K_CPU_TYPE_68000:
  case M68K_CPU_TYPE_68010:
  case M68K_CPU_TYPE_68EC020:
  case M68K_CPU_TYPE_68020:
  case M68K_CPU_TYPE_68EC030:
  case M68K_CPU_TYPE_68030:
  case M68K_CPU_TYPE_68EC040:
  case M68K_CPU_TYPE_68LC040:
  case M68K_CPU_TYPE_68040:
    return 1;
  default:
    return 0;
  }
}
```

### 2. MOVEC Translator Implemented (`src/m68xkcpu/jit_block.c`)

Implemented `jit_translate_movec()` to handle the MOVEC instruction (Move to/from Control Register), which is critical for:
- CPU identification (PCR register)
- Vector Base Register setup (VBR)
- Cache control (CACR)
- Function code registers (SFC/DFC)

**Supported Control Registers:**
- `0x804` - VBR (Vector Base Register)
- `0x800/0x801` - SFC/DFC (Function Code registers)
- `0x805` - CACR (Cache Control Register)
- `0x808` - PCR (Processor Control Register - returns 0x0400 for 68040)

### 3. EXTB Translator Implemented (`src/m68xkcpu/jit_block.c`)

Implemented `jit_translate_extb()` for the EXTB (Sign Extend Byte) instruction:
- Format: `0100100011000nnn` (0x49C0-0x49C7)
- Extends bit 7 of Dn to fill all 32 bits
- Uses AArch64 LSL #24 followed by ASR #24 for sign extension

### 4. AArch64 Shift Macros Added (`src/m68xkcpu/jit_emit_aarch64.h`)

```c
#define AARCH64_LSL(rd, rn, shift)      (0xD320F800u | (((shift) & 0x3F) << 10) | ((rn) << 5) | ((rd) & 0x1F))
#define AARCH64_LSR(rd, rn, shift)      (0xD320FC00u | (((shift) & 0x3F) << 10) | ((rn) << 5) | ((rd) & 0x1F))
#define AARCH64_ASR(rd, rn, shift)      (0xD340FC00u | (((shift) & 0x3F) << 10) | ((rn) << 5) | ((rd) & 0x1F))
```

### 5. Integration Updates

- Added `EXT` and `EXTB` to `jit_family_codegen_supported()`
- Added `EXTB` case to `jit_block_emit()` switch statement
- Added `jit_translate_extb()` declaration to `jit_translate.h`

## Usage

### Enable JIT with 68020/68040

```bash
# In your config file (default.cfg or min.cfg):
cpu 68020
# or
cpu 68040
jit m68xkcpu

# Run with JIT execution enabled:
sudo PISTORM_M68XK_EXEC=1 ./emulator -c min.cfg
```

### No Override Needed

The `PISTORM_M68XK_ALLOW_UNSUPPORTED_CPU=1` environment variable is no longer needed for 68020/68040 - they are now natively supported.

## Fallback Behavior

Instructions not yet implemented in the JIT will automatically fall back to Musashi interpreter:
- Bitfield operations (BFxxx)
- Complex addressing modes
- 68020/68040 specific instructions not yet translated

This allows incremental implementation while maintaining correctness.

## Next Steps for Full 68020/68040 Support

### High Priority (Boot Critical)
1. **LEA** - Load Effective Address (common in 68020+ code)
2. **MOVEM** - Move Multiple Registers (stack operations)
3. **MOVEP** - Move with Displacement

### Medium Priority (Performance)
4. **Bitfield operations** (BFxxx) - 68020+ specific
5. **MULS/MULU** - Multiply instructions
6. **DIVS/DIVU** - Divide instructions

### Lower Priority
7. **CHK** - Check Bounds
8. **LINK/UNLK** - Stack frame operations
9. **TRAP variants** - Exception handling

## Architecture Notes

The implementation follows the unified JIT model:
- **X19** holds `&m68ki_cpu` (CPU state pointer)
- Translators **append** to `jit_emit_context_t`
- Single block builder manages code cache
- Unsupported instructions fall back to Musashi

This design allows incremental instruction implementation without disrupting the overall architecture.
